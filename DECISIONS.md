| G2 | Vertex edits that bend a face | Split the bent face into flat triangles; dents still refused | Refuse the move | **Approved** (2026-11-01); dents allowed since G4 |
| G4 | Free vertex editing (amends D3 and G2) | Corners move anywhere. A brush that stops being convex becomes an **edited mesh**: explicit corners and flat, convex polygons (bent or dented faces become triangles), saved in the brush data (scene format 3). It draws, collides (exact triangles when still), paints and vertex-edits like any brush; carve, clip, merge, hollow and Apply cut skip it with a message. A loop cut (Ctrl+R) adds rings of edges to move. An edited mesh that is convex again, with no extra corners, turns back into a normal brush | Keep refusing dents | **Approved** (2026-11-01, at the user's request) |
| G3 | Where brush geometry lives once transforms nest | Brush faces are stored relative to their parent; every entity's transform is local to its parent; moving or rotating a group carries its contents without rewriting them | Keep brushes in world space (Hammer-style) | **Approved** (2026-11-01) |
| P1 | How a placed prefab copy is stored (amends D5) | In full in the scene, with a hidden link per object; on save each object records which values differ from the prefab; editing the prefab updates every copy except those values | Store only the differences and rebuild copies from the prefab file on open | **Approved** (2026-11-01) |
| S1 | Where scripts live | A Script component on the object it controls (“this door”), travelling with copies and prefabs; game-wide rules go on a “Game rules” object | Separate script files that name the objects they control | **Approved** (2026-11-01) |
| S2 | First block set | Core set: events (game starts, enters/leaves a zone, message, every N seconds); actions (move, turn, return to start, show/hide, turn on/off, wait, send message, log, set/change variable); If/Otherwise, Repeat, Repeat forever, Stop; variables, maths, comparisons, random, text | A smaller first set | **Approved** (2026-11-01) |
| D12 | Editor UI stack | React + TypeScript + Zustand + Vite, CocoaCanvas CSS copied into a UI package | Vanilla TS like CocoaCanvas; Svelte | **Approved** (2026-11-01) |

## Log

- **2026-11-02** — Routine choices for weapons (A1, reversible): a weapon is an item with weapon settings, so the hotbar, the inventory, shops and saved progress already work with weapons, and ammo is just another item. Ready-made weapons follow Half-Life's numbers. Bullets are instant rays, swings are short rays, and projectiles are simulated by the game rather than as physics bodies, so they never tunnel. Blasts fall off linearly, are blocked by fixed and scripted geometry, and hurt their own shooter. Hits run a new event, “When this is hit”, on the object and everything it is inside (as Use does). Weapon code lives in its own module that takes a shooter and a direction, so creatures can use it later.

- **2026-11-02** — Routine choices for armour and chargers (A1, reversible): armour follows Half-Life's numbers (ratio 0.2, bonus 0.5, at most 100, lost on dying) and is skipped by falls and drowning. It shows under health only once the player has some. Scripts give and read it like health. The battery is a recipe of ordinary blocks, like the health pack. A charger is a component, because holding a key is a game rule rather than a script event. The game now passes whether Use is held, and chargers give a little on each physics step.

- **2026-11-02** — Routine choices for ladders and water (A1, reversible): both are components on brushes (Hammer's func_ladder and func_water) and Brush tool kinds. A ladder is an invisible zone climbed Half-Life's way: forward climbs while looking ahead or up, and goes down while looking down. Water is drawn with its own materials, outside the level's hidden-face removal, so walls next to it stay visible. Swimming follows Source's water move: 80% speed, friction 4, sinking 60 u/s, and a water jump onto ledges. Drowning follows Half-Life: 12 s of air, then 10 health a second. Floating is a lift that grows with depth plus damping, so bodies settle at the surface whatever their weight. The view under water uses the water's colour as fog and hides the sky. Both kinds stay put when scripts target them.

- **2026-11-02** — Routine choices for the Materials workspace (reversible): materials belong to the project (`settings.materials` in the project file), so every scene shares them, not to a scene like screens. Faces refer to them by a fixed id (`mat/…`), so renaming never breaks a level. Edits are undoable through the scene's history and written to the project file a moment after the last change. Editing a material restyles the materials already drawn rather than rebuilding the level. Metal and polished materials reflect a picture made from the sky colours; matte ones are left almost as they were, so existing levels keep their look. A deleted material shows Source's missing-texture check. Exports carry only the materials the scene uses. In other workspaces, Ctrl+Z, Ctrl+Y and Ctrl+S now also work while a slider, switch or colour well has focus.

- **2026-11-01** — Routine choices for the player's feel (reversible, at the user's request: the view jittered and the player was slippery). Grip is firmer than Source's: accelerate 14, friction 8 (stop speed 100), air cap 60, so a run stops in about 0.2 s and 17 u. A stair riser no longer counts as a wall (speed is kept), with a Source-style step-up when the physics engine's own fails. The view height eases over steps, bumps and crouching (never more than 1.5 steps behind; exact while jumping or falling). Single mouse movements over 300 px while playing are ignored as pointer-lock glitches.

- **2026-11-01** — Approved by the user after the benchmark: **M1** single-player for now; an option to host (and join) games comes later, so the runtime keeps game state in one place and input separate from simulation. **T1** voxel terrain that also supports heightmaps: terrain is a voxel field (chunked, meshed with surface nets in a worker, a collider per chunk), so caves, overhangs and digging are possible; a heightmap image can be imported to fill it, and sculpting includes heightmap-style raise, lower, smooth and flatten; up to 8 painted materials. **Models** glTF/GLB import, static and animated. **Navigation** navigation meshes generated with recast-navigation (WebAssembly) from the level and terrain. **Screen UI** a visual UI editor (text, images, buttons, bars, lists in anchored boxes) controlled by blocks.

- **2026-11-01** — The user set the benchmark (BENCHMARK.md): Basic, a typical Roblox game (tycoon, Natural Disaster Survival, Grow a Garden, Pet Simulator); Advanced, Slime Rancher and Half-Life 1. The roadmap now follows benchmark steps B1–B5, A1, A2, T1. Pending approval: M1 multiplayer, T1 terrain, model import, navigation, screen UI. Routine choice (reversible): health and score are game rules in the project file (`settings.game`), both on unless switched off; switched-off blocks still compile, with a warning, and do nothing.

- **2026-11-02** — Fix after play-testing (reversible): “Move by” and “Turn by” add to the end of the move or turn they interrupt instead of the object's current place, so paired moves (a plate down 6 on enter, up 6 on leave) can't drift when the player steps on and off quickly.

- **2026-11-02** — Routine choices for B4, export and saved progress (reversible): the editor's build carries a second page, the game player, which reads `game/game.json` and assets from beside it; a web export copies only the player's files (from Vite's manifest). A desktop export copies an Electron runtime and puts a small game shell in it as its app, serving the web game from a private `game://` scheme, which keeps D9 (Electron runtime shell) without needing build tools on the user's computer; the runtime is the editor's own for its system and is downloaded once (same Electron version, x64) for the others. Installers and signing (electron-builder) stay with Phase 9. Saved progress is what the creator marks: game values marked kept and, by a game rule, the inventory; it is written to browser storage as it changes and read at start; the real clock is a value so things can grow while the game is closed. Saving the state of the world is left for later.

- **2026-11-02** — Routine choices for B5, the screen UI (reversible): screens and items are saved in the scene's settings (`settings.ui`), so they undo like any edit; layout is a 1280 × 720 reference screen scaled by the window's height, with nine anchors and offsets counted in from the anchored edges; texts show values with `{Name}`; a screen can free the mouse for its buttons while the keys still move the player; the inventory is a count per item in pick-up order, shown by a hotbar element (1–9 and the wheel pick a slot, a left click uses it). At the user's request the editor is a full-window workspace switched from the top bar (Scene · Screens · Materials, the last a placeholder for the material editor), with the scene kept loaded underneath; the scene's keys are off while another workspace is shown. Finishing it: lists (own rows or the inventory, scrolling, columns for grids), elements placed inside panels (one level of box per parent, hidden with it, new ones stacked from the top), draw order as list order, key events for letters the game doesn't use and Tab, and Esc pausing in menus as it does with the captured mouse.

- **2026-11-02** — Routine choices after play-testing feedback (reversible): the player's collision shape changes from Source's box to an upright cylinder (radius 16, 72 tall; crouched 36), because a box stops dead against the facets of round brushes; the flat bottom keeps steps and edges like the box, and step-up is also tried for a few frames after leaving the ground so tight stairs never stall. The physics engine's character movement sticks on kinematic bodies and goes wrong exactly above a convex hull's own origin, so moving objects get fixed stand-in copies that the player moves against (the real ones still push physics objects), every hull's origin sits at an off-grid point, and the player is carried by whatever moving object they stand on (no jumping while it moves). Messages sent every frame count as one message that starts and, 0.1 s after the last, stops; “Repeat while” waits a frame each time round. Hinged doors are recipes that set the pivot on the door's long-side end and use a new absolute “Turn to” block. Brush geometry keeps computed polygons per brush (brushes are never changed in place), which made 32-sided spheres select instantly. Models gain a Collision setting (none, box, hull, exact; moving ones use the hull); a Collision shape without Physics is now a still collider.

- **2026-11-01** — Routine choices for health, damage and score (reversible): the player has 100 health; scripts hurt and heal with plain blocks (“Hurt the player by”, “Heal the player by”, “Change the score by”, values “the player's health” and “the score”, event “When the player dies”) rather than special components, so pickups, hurt zones and lava are recipes made of ordinary blocks (V2). At 0 health the player starts again at the Player start with full health; the score is kept. Falls hurt with Half-Life 2's numbers (safe below 526.5 u/s on landing, fatal at 922.5), and falling out of the world counts as dying. The score only shows on screen once a script uses it. Lives, game over screens and saved high scores are left for later.

- **2026-11-01** — Routine choices for COL (reversible): an invisible collider is a material (`tool/col`, like Hammer's tool textures), so single faces or whole brushes can be COL and it survives carving and clipping; the brush tool offers COL as a kind for drawing collision-only blocks; in the editor it is see-through with purple stripes and the letters COL; in Play its faces are skipped when drawing and kept for physics; a COL face never hides a visible face pressed against it.

- **2026-11-01** — Routine choices for pivots (reversible, at the user's request after “turn” spun objects around the world origin): every object has a pivot, by default the middle of a brush, the middle of a group's brushes, or a point object's position; a set pivot is an internal `pivot` component, stored for brushes as an offset from the brush's middle (so moving or reshaping keeps it on the brush) and for other objects as a point in their own space. The gizmo sits on the pivot of a single selection; scripts' move and turn act around it. Edit pivot mode (O) makes the move gizmo move only the pivot, snapping to any corner. Player speeds lowered to Half-Life 2's: run 190, walk 100, crouch 64 u/s (Source's 320 is a sprint).

- **2026-11-01** — Routine choices for recipes (V2, reversible): a recipe only ever adds ordinary blocks (plus a trigger zone beside the object when it needs one), merged into the object's script as one undo step; doors open by their own height; the use-door closes by itself after 3 seconds, because an open door is above the player's reach; buttons and plates talk to doors with the message “open”. Hidden and switched-off objects no longer block or catch the player.

- **2026-11-01** — Approved G4 (free vertex editing, edited meshes, loop cut) at the user's request: the vertex tool was too restrictive. Scenes move to format 3; older scenes open unchanged. Play now puts you in the player's shoes when the scene has a Player start (Source-style movement from D4: a 32 × 72 × 32 box like Source's hull, which steps and slides more cleanly than a capsule); without one, Play stays the physics preview. Routine choices: the first Esc frees the mouse and the second stops; F5 always stops; while the mouse is captured every other key belongs to the game; E uses whatever is within 96 u of the crosshair, and “When the player uses this” fires on that object and every group it is in.

- **2026-11-01** — Approved S1 (scripts on objects) and S2 (core block set) at the start of Phase 5.

- **2026-11-01** — Approved P1: prefab copies are stored in full with tracked changes, so scenes open and play without their prefab files. This replaces D5's “instances store only overrides”; the per-field Apply and Revert from D5 stay.

- **2026-11-01** — Routine choices for components and physics (reversible): one component registry in core drives the Inspector and the runtime; long multi-choice fields show as a dropdown so the Inspector never overflows; trigger zones are brushes with a trigger component (amber), and subtract brushes moved to coral so the two never look alike; physics runs in game units with Rapier's `lengthUnit`; an object's own Bounce wins over what it lands on; Rapier 0.21 loads on first Play; the CSP allows WebAssembly compilation only.

- **2026-11-01** — Approved G3 (brushes relative to parent) and the start of Phase 4. Scenes move to format 2: transforms are local to the parent and brush faces are in the parent's space. Format-1 scenes are upgraded on open (with a backup) without moving anything: groups get an identity transform, other children are re-expressed relative to their parent.

- **2026-11-01** — Routine choices for the end of Phase 3 (reversible): polygon outlines are made convex (dents filled in) rather than split into several brushes; levels of 64+ brushes build in a background worker inlined into the bundle as a blob (no extra files to load from disk); while a build runs, only the latest edit is queued. Number fields now derive their text during render instead of copying props into state in an effect, which removed a render loop seen when pasting many objects quickly.

- **2026-11-01** — Routine choices for multi-select, groups, clipboard and snapping (reversible): groups follow CocoaCanvas (a click selects the outermost group, double-click or Enter steps in, Esc steps out); a group's Visible and Locked switches apply to everything inside; each paste is offset one grid step further and a cut pastes back in place; snapping to corners grabs the moving corner nearest the cursor and shows it in the guide colour; grid snapping while moving is relative to the start of the drag.

- **2026-11-01** — Approved G1 (live subtract brushes) and G2 (split bent faces) after reviewing the geometry engine.

- **2026-11-01** — Routine choices made during Phase 2 (reversible, recorded for reference): Y-up coordinates with degrees in YXZ order; esbuild for the main/preload bundles and Vite for the UI; the editor grid is a shader rather than line geometry; editor-only overlays use Three.js directly while game content will go through the render adapter.

- **2026-11-01** — Editor mockups approved. Scripting must be approachable: node-graph-first design replaced by plain-language blocks.
